# Week 4 - Pick the Stack

## My Constraints

- Free tools only.
- Beginner-friendly enough for me to maintain and explain.
- The portfolio must show AI, data, backend, and cloud projects clearly.
- It needs to support project screenshots, GitHub repository links, case study text, and possibly embedded demos later.
- Nothing needs to be dynamic at launch. A contact form can come later.

## Option 1 - No-Code Builder

Build:
Carrd, Framer, or Canva website builder.

Free hosting:
The builder's free hosting or published link.

Backend needed:
No.

How well it shows my work:
Good for a simple one-page portfolio, but less ideal for showing several technical case studies with code links, screenshots, and structured project pages.

Trade-off:
Fastest to publish, but less useful as proof that I can build and maintain a technical portfolio myself.

## Option 2 - Plain HTML/CSS with AI Support

Build:
A simple static website using HTML and CSS, supported by AI while I keep the structure understandable.

Free hosting:
Netlify drag-and-drop or GitHub Pages.

Backend needed:
Not at launch.

How well it shows my work:
Strong fit. It can show screenshots, project cards, long-form case studies, GitHub links, and a clean visual identity without unnecessary complexity.

Trade-off:
I need to maintain the files myself, but that is also useful practice. The site stays simple enough for me to understand and explain.

## Option 3 - Framework Site

Build:
React, Next.js, or another frontend framework.

Free hosting:
Vercel, Netlify, or Cloudflare Pages.

Backend needed:
Not necessarily, unless I add dynamic features later.

How well it shows my work:
Very flexible and powerful, especially for future interactive demos.

Trade-off:
More setup, more moving parts, and more maintenance than I need right now. It could slow me down before I have enough portfolio content ready.

## Chosen Stack

I chose plain HTML/CSS with AI support, hosted for free on Netlify.

## Why I Chose It

This is the smallest stack that does the job well. My portfolio needs to show real work: screenshots, repositories, case studies, and clear explanations. It does not need a backend at launch.

I can maintain this stack because the files are simple, readable, and easy to change. It also helps me practice the fundamentals of how a website works while still letting me ship quickly.

I did not choose no-code because I want the portfolio itself to be a small piece of technical proof. I did not choose a framework because it is more power than I need right now and would add maintenance before the site needs dynamic features.
